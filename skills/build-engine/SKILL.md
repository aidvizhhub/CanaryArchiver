# CanaryArchiver — сборка и выдача копий воркспейса

Служба охраны воркспейса: каждая разданная копия несёт **уникальную фразу-канарейку**
(обычным текстом БЕЗ маркера, отдельными строками на 60-й позиции и в
хеш-позиции второй половины CLAUDE.md — canary trap: получатель с одной
копией не знает, что фраза — метка), собирается в **ZIP с паролем
из окружения `GUARD_ZIP_PASSWORD`** (или config.py), сохраняется как
**папка-улика** (архив + info.md) и заносится в **реестр** log.md.
Утекла копия — `guard.py --leak <файл|zip|папка>` найдёт фразу и назовёт,
чья копия и когда выдана.

Паттерн: honeytoken/canary-token (thinkst, GitGuardian) + chain of custody
(цифровая криминалистика).

## Где что лежит (CanaryArchiver)

- Корень CanaryArchiver — по умолчанию `$WORKSPACE_ROOT/../CanaryArchiver`
  (рядом с воркспейсом). Если скилл лежит внутри CanaryArchiver
  (`skills/build-engine/`) — корень это `../..`.
- `guard.py` — сборка и выдача; `archive.py` — ротация эпох версий;
  `add_watermarks.py` — разметка знаков;
  `dist/` — папки-улики текущей эпохи; `archive/<версия>/` — эпохи прошлых
  версий (log.md + dist/); `log.md` — реестр выдач; `version.txt` — версия
  текущей эпохи.

## Workflow выдачи (императивно)

1. Получить от владельца: ник/имя получателя (обязательно), при желании ID.
2. Придумать фразу-код по паттерну `<ник>-<слово>-2026` (латиницей); фраза
   может быть ЛЮБОЙ, но уникальной.
3. Запустить:
   ```bash
   cd "$WORKSPACE_ROOT/../CanaryArchiver"
   export GUARD_ZIP_PASSWORD=...   # пароль архивов
   python3 guard.py --fp "<фраза>" --user "@<ник> <имя>" [--id <номер>]
   ```
4. Убедиться, что вывод содержит: канарейка «…» проверена ✓, архив собран,
   выдача сохранена (папка в dist/), CLAUDE.md восстановлен (сверка sha256).
5. Отдать владельцу: путь к архиву (`$WORKSPACE_ROOT/../workspace-<версия>.zip`),
   пароль, фразу-канарейку и папку-досье из dist/.
6. Закоммитить реестр: `git add log.md && git commit -m "выдача <ник> (<фраза>)"`.

## Флаги guard.py

| Флаг | Что делает |
|---|---|
| `--fp "фраза"` | метка копии (любая, уникальная; вшивается без маркера в 2 места CLAUDE.md) |
| `--user "@ник"` | юзернейм получателя — ТОЛЬКО в реестр log.md и улику info.md (в файл не вшивается — палевно) |
| `--id N` | номер/ID аккаунта — тоже только в реестр/улику |
| `--auto` | авто-серийник `copy-YYYYMMDDHHMMSS` |
| `--force` | разрешить повтор уже выданной фразы |
| `--store` | показать хранилище выдач (папки dist/) |
| `--leak <путь>` | нашёл утечку (файл/zip/папка) — ищет фразы из log.md, называет получателя |
| `--who "фраза"` | фраза → чья копия: прямой запрос по реестру (нашёл слово глазами — спроси у скрипта) |
| `--rebuild <путь>` | перевыдача из готового билда: zip или папка dist/ прошлой выдачи как база — старые метки снимаются, новая фраза через `--fp` |
| `--rotate` | эпоху прошлой версии — в `archive/<версия>/` (log.md + dist/, move-only), начать свежую; при выдаче новой версии срабатывает автоматически |
| `--from <вер>` | с `--rotate`: из какой версии архивировать (легаси-переход, принудительно) |
| `--dry-run` | план без изменений |
| `--root <путь>` | корень воркспейса (по умолчанию `$WORKSPACE_ROOT`) |

## Ротация версий (archive/)

Версия воркспейса сменилась (VERSION 2.4 → 2.7): перед выдачей guard.py
сверяет VERSION с `version.txt` и автоматически увозит log.md и dist/
прошлой эпохи в `archive/2.4/` (move-only, ничего не удаляется), начинает
свежую эпоху. Реестр копий полон ВСЕГДА: `--leak`/`--who`/проверка
повтора фразы ищут по всем реестрам (текущему + archive/*/log.md) —
канарейки уникальны навсегда, цепочка улик не рвётся. Ручной переход:

```bash
python3 guard.py --rotate --from 2.4   # заархивировать текущее как эпоху 2.4
```

## Перевыдача из готового билда (`--rebuild`)

Когда владелец говорит «возьми уже собранный билд из dist/ и сделай с
другой фразой» — НЕ пересобирать из корня воркспейса, а взять готовый:

```bash
python3 guard.py --rebuild "dist/20260813-…_старая-фраза_sha12" --fp "новая фраза" --user "@ник"
# или путь прямо к zip: --rebuild dist/.../workspace-2.4.zip
# план без записи в dist/log.md: добавить --dry-run
```

Что делает: распаковывает базовый архив (пароль из `GUARD_ZIP_PASSWORD`),
**снимает старые метки** (строки фраз из реестра log.md + палевные
комментарии `<!-- GUARD fp -->` билдов до v3), вшивает новую фразу тем же
v3-алгоритмом, пересобирает zip той же командой, что make_archive.sh,
проверяет (канарейка ×2, по всем текстовым файлам нет GUARD fp/старых
фраз/юзеров) и кладёт **новую** папку-улику + строку в log.md. Старые
дисты не переписываются. Фраза должна быть новой (`--force` — осознанный
повтор).

## Водяные знаки (add_watermarks.py)

```bash
python3 add_watermarks.py --stats     # сколько знаков на сколько файлов
python3 add_watermarks.py             # докачать до 3 знаков/файл (идемпотентно)
python3 add_watermarks.py --check     # отчёт без записи
```

## Success criteria

- Вывод guard.py: канарейка вшита и проверена в архиве (2 места), CLAUDE.md
  восстановлен со сверкой.
- В `dist/` появилась папка `<время>_<фраза>_<sha12>/` с
  `workspace-<версия>.zip` и `info.md` (фраза, юзер, id, дата, полный sha256).
- В `log.md` — новая строка с фразой/юзером/архивом.

## Failure modes

| Симптом | Что делать |
|---|---|
| `фраза уже выдавалась` | взять другую фразу или `--force` (осознанный повтор) |
| `сборка архива не удалась` | сработал секрет-паттерн make_archive.sh или нет `zip` — разобраться и повторить |
| канарейка «НЕ НАШЛАСЬ» в архиве | проверить, что фраза реально вшилась в CLAUDE.md (2 места без маркера) и архив собрался из актуальных файлов |
| CLAUDE.md не восстановился | взять `CLAUDE.md` из git воркспейса (`git checkout -- CLAUDE.md`) — guard делает это сам в finally, но при убийстве процесса возможен след |

## Gotchas (проверено на практике)

- **Пароль везде один**: `GUARD_ZIP_PASSWORD` — и в `make_archive.sh`
  (воркспейс), и в `guard.py`. Меняешь — меняй в обоих.
- **ZIP собирается staging-каталогом** (make_archive.sh): `zip -@`
  не умеет префиксовать имена и терял первый файл — не «чинить» обратно.
- **ZipCrypto ≠ AES**: защита от случайного любопытного, не от криптоанализа.
  Для цели «пароль-визитка + канарейка» — достаточно.
- **dist/ не в git** (`.gitignore` в CanaryArchiver), `log.md` — в git:
  реестр версионируется, бинари нет.
- **Дисты до v3 палевные**: внутри CLAUDE.md комментарий
  `<!-- GUARD fp: фраза · user -->` (метка+юзер в файле). Не раздавать
  повторно и не брать за основу вручную — `--rebuild` сам вычистит.
- **База для --rebuild — дист БЕЗ распакованной папки `workspace-2.4/` внутри**
  (2 элемента: zip + info.md): иначе незашифрованная копия с канарейкой
  лежит на диске. `--rebuild` кладёт новую выдачу всегда 2 элементами.
- **Фраза уникальна навсегда** — это метка: не переиспользовать фразы разных
  получателей (реестр это ловит).
- **Зеркала после разметки** получают разные вариации знаков (хеш по пути) —
  после прогона разметчика синхронизировать зеркала явно.
- **Разметчик не вставляет знаки в импорты** (.py) — это учтено, не откатывать.
- **Воркспейс сам себя чинит**: make_archive.sh исключает make_archive.sh,
  add_watermarks.py (если вернётся в scripts/), db/, *.zip, *.bak, reverser.
